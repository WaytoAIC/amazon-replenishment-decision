# 自主查数与归因流程

用于销量变化归因、供应进度调查与补货复评。先补查再给业务判断；不要求业务部门提供已有接口能够取得的数字。

## 1. 调查边界与结束条件

- 读取项目私有 scope 与稳定匿名映射，锁定授权销售对象。销售对象与采购商品不是同一层级；后者跨店共享时可读取对应单据追链，但不得扩展经营分析或默认全部分配给本案例。
- 先复用现有授权只读入口、已存资料与 schema，不新建应用、不打印凭证。原始响应、真实映射和请求参数仅进被忽略的私有目录；可复用说明、代码与测试不得硬编码真实案例标识。
- 每条依据记：接口/资料、业务范围、查询起止/分页、实际查询时间、源快照/更新时间、映射依据。新查到旧快照要保留两个时间。
- 明确区分“成功且有记录”“成功无匹配记录”“查询失败/权限不足”“接口无该能力”。空值或失败不能写成无活动、无订单、无在途。
- 追查与当前决策有关的链路，查到足以判断或到达能力边界就结束；已知缺少动态节点时，不反复调用静态货件接口。展示哪些已查清、哪些为推断、哪些仍未知及其业务影响。

## 2. 销量变化：先查经营动作，再拆流量与转化

1. 用完整且可比的窗口取得销量、日均及基线；同时读取流量、平均售价、广告花费/归因订单/销售额、商品折扣与优惠券等费用，以及已有活动/变更记录。利润使用已确认赛狐指标。
2. 对齐商品、站点、币种、日期和数据粒度；商品分析返回空 mskuList 时，可用经过唯一性验证的 productIdList 与私有在线商品映射，不能按结果行序猜测。不同来源销量核对，无法解释的冲突保留。
3. 若某日有销量但访客为零或缺失，逐日复核；不能擅称是数据延迟。两周比较可只用双方均有正访客数的同星期日期，完整周销量仍单列，输出剔除日期及有效样本数。样本不足或无有效日时不能外推整周归因。零销量且有访客是有效观察，不得剔除。
4. 辅助分解：销量 = 访客 ×（销量/访客）。这里是单位销量转化水平，不冒充订单转化率；广告订单也不能从总销量件数中相减以推算自然销量。没有可靠访客来源拆分时，不判断自然流量是否下降。
5. 已核实：具体数字和动作记录。推断：流量/转化与广告、促销的共同变化。未知：经营意图、活动结束日、长期持续性或外部根因。花费增加不等于预算被上调，平均售价变化不等于页面调价，优惠券费用出现不证明开券日期，未找到变更记录不证明没有调整。费用分类可能重叠，不任意相加。
6. 只有时间先后、动作记录及影响链路支持时才把原因定为主动策略变化；外部季节、竞争或排名归因需要对应证据。缺证据时保留候选解释，不用猜测填满诊断。

## 3. 供应进度：沿关联链找卡点，避免重复采购

按关联标识连接：采购计划 → 采购单 → 国内到货 → 发货单 → FBA货件 → 接收 → 可售。每批同时保留数量、状态、原/新日期、归属和关联依据；单据数量不能跨环节累加。

- **待采购计划**：检查计划数量、箱数、已采购数、采购单关联、销售对象归属；有审核时间不代表已批准。计划已处理/转单不代表采购已下单。
- **采购单**：核下单状态、实际下单时间、到货/未到数量及有效性。草稿不算确定供应；可能存在系统外订单时明确未知，先核对旧单及新计划再建议新增。
- **已发批次**：查发货单实际发运字段、物流单号、货件状态、预计到仓窗、逐商品已接收量。已发运批次的当前执行阶段属于物流/接收，不再把“催这批生产”列为主要动作；供应链仍可负责备选供给。
- **归属**：仅匹配同一采购商品、但店铺/MSKU为空的计划是待分配记录，不能充当目标商品已落实供应；聚合库存字段也不能替代本案例库存。
- **残量**：逐批计算发送与接收差额；历史超收单独保留，不能跨批抵消时间缺口。极小历史残量不升级为整个商品的物流根因。
- **日期**：到仓/清关/接收/可售各有语义；不同节点的预计日期不同，不直接判定延误。记录出现“发运早于采购录入”或几秒内收货时，不用它推算真实生产交期。追踪号校验状态不等于运输状态。
- **动态节点**：静态状态不能证明当前位置、清关完成或保证可售日期。查已有承运商/货代只读入口及备注；没有对应能力时，只请求最新节点或承诺，不让部门重抄整份订单。

## 4. 现有赛狐入口与调用要点

若使用者已安装经过验证的 `amazon-replenishment-plan` 只读适配器，可复用其 `scripts/sellfox_readonly.py`；本包不捆绑该适配器，不存在时先使用文件方案，凭证由使用者受控配置读取。该适配器的只读白名单可能未收录下列路径；先用已存官方 schema 核对再在单次读取进程添加具体已验证路径，不能改为允许任意请求或写接口。接口参数变更按实际 schema 核查，不无限试字段。

| 数据 | 已使用的只读路径及要点 |
|---|---|
| 销量/访客 | `/api/productAnalyze/V2/pageList.json`；dimType=3、subType=0、精确MSKU、授权店铺/市场、明确日期/币种；fields需显式提供，已验证sessions/pageView/conversionRate/salePrice；取fieldsMap.currValue及自动返回的saleNum。不要假设旧版adCost字段可用 |
| 广告/促销/利润 | `/api/sale/profit/product/v2/pageList.json`；type=msku、精确搜索、日期/币种及结算口径显式保留；财务广告归因窗口不一定等于销量窗口 |
| 商品变更 | `/api/order/api/product/getProductChangeRecordList.json`；限定店铺和时间，结果精确匹配；不覆盖所有广告/活动变更 |
| 现货 | `/api/inventoryManage/fba/pageList.json`；核snapshotDate、可售与在途；多商品请求失败可依schema按单商品查，不把失败当零 |
| 采购计划 | `/api/purchasePlan/search.json`；精确commoditySku，实测需要createTimeStart/createTimeEnd；分页完整。必要时回溯关联旧计划，不局限于销量比较周 |
| 采购单 | `/api/purchase/page.json`；覆盖未下单与执行中状态，并按关联purchaseNos追查已收货单，不能只看一个状态 |
| 货件 | `/api/inbound/shipment/page.json`、`/api/inbound/shipment/details.json`；复核已知活动批次并查后续新建批次；逐商品匹配MSKU/FNSKU，不能用整票多商品总量 |
| 发货/物流 | `/api/fba/shippingOrder/detailByShipSn/v2.json`；按货件关联shipSn追查，核实际发运、预计节点、物流记录。未提供运输事件时不声称已掌握实时轨迹 |

所有分页读完或标明截断；受限状态与历史窗口要披露。请求失败先查响应与schema，修正必要参数后有限重试；鉴权/白名单问题遵循入口停止规则。

## 5. 交付及验证

业务结论之前已有自主调查；展示仍以业务异常开头，而非堆请求日志。每商品列：销量证据与可解释范围、供应已到哪一步、风险计算、建议动作。末尾集中列真正剩余事项，每项给“已查来源及边界 → 缺什么 → 影响哪个决定 → 建议/提供何种入口”，不重复问已确认规则。

人工事项限于：未记录的经营计划/意图、无归属计划分配、系统外订单/实物、供应商可发与物流可售承诺、权限外取舍。助手已取到的数字、状态及计算不再分给部门；没有证据不判责任。老板只决定目标、资金、权限外费用或不可避免损失，不审批每项例行查数。

真实案例复验使用明确截点的只读证据，允许同日重放已取快照，但必须写“证据重放，未刷新实时状态”。至少核查：缺失流量处理、广告件/单口径、计划与订单关联、归属、分阶段去重、时间语义及最终人工问题是否必要。合成测试只验证计算约束，不能替代真实案例判断。
