# 外部市场证据：卖家精灵 MCP

目的：验证内部经营变化是否同时出现市场、关键词或竞争变化。先查已有内部经营动作，再用外部证据验证候选解释。按当前问题选择调用，不固定扫全套接口，不创建监控。

## 最小调查与工具路由

| 要判断的假设 | 可用工具（以当前工具清单/schema为准） | 关键限制 |
|---|---|---|
| 价格、Buy Box、BSR、评分或卖家变化 | `keepa_info`；必要时 `asin_detail_with_coupon_trend` / `asin_coupon_trend` | keepa_info不含真实销量；BSR变小是排名改善，不等于本变体卖了多少；商品状态不证明自己的FBA可售 |
| 站内需求/季节变化 | 从已授权种子词或 `traffic_keyword` 选相关词，再 `keyword_research_trends` 或 `aba_research_trend` | 月度数据不能解释某一周全部变化；关键词相关性须确认，购买量/预测不等于本店销量 |
| 自然与广告线索变化 | `traffic_keyword_stat`、必要时 `traffic_keyword` / `traffic_source` | 流量词数量/覆盖占比不等于访客占比；nearly与历史月未必可比，不替代后台Sessions/广告归因数据 |
| 竞争加剧/市场共振 | `asin_competitor` 找候选，验证用途/变体/价位后选少量可比商品；查其价格/BSR/促销；需要类目依据时用 `product_node`、`market_product_demand_trend` | 竞品只是平台推选，不能未经验证视为直接替代品；本品BSR变化不证明整个市场增长或竞争造成销量下降 |
| 站外需求 | 有必要才查 `google_trend` | 指数不是绝对搜索量，也不是Amazon站内需求 |

先检查真实工具是否存在、权限和额度；只在授权范围内查询本品及与问题直接相关的公共市场商品。不要在用户输出中展示真实标识、词、类目或商品链接。不存在的工具不编调用；缺接入按 [首次使用引导](onboarding.md) 降级。

## 对齐与证据等级

1. 每次请求保存站点、请求对象、起止时间/月份/时区和实际查询时刻。返回后核ASIN、dataAsin、父子体、排名参考节点；父体/其他变体数据只能作对应层级线索，不能冒充本SKU销量或排名。类目参考节点更换时，跨节点BSR不能直接比较。
2. 按timePoint排序，过滤请求范围外数据；负数哨兵、空数组和缺失不当0。日去重用明确时区；价格/BSR序列不向前填充空日。用 `scripts/market_series.py` 可输出匿名序列覆盖和首末有效观测，但不能用它自动确定根因。
3. 披露实际最早/最晚观测、天数及与内部数据的重叠期。查询区间不是数据覆盖承诺；观测到19日就不能说覆盖到22日。没有同周期数据则结论降级，必要时给可导入的供应商导出替代。
4. 内部费用人民币与外部当地售价分别标币种；未确认换算不横比金额。外部展示价格不等于折扣后真实成交价；优惠券需单独证据。供应商预测、采样、估算均保留来源标签。
5. 输出三层：已核实的外部观测；它支持/削弱哪个内部候选解释；仍缺什么才能确认。可比词与多竞品同周期变化可增强市场判断，但相关性不直接证明责任或因果。
6. 核定需求、正式补货量、供应承诺仍以内部真实记录和经确认的业务修正为准。不用市场预测覆盖赛狐销量，也不把BSR改善乘成销量增长系数。冲突保留两源及时间/层级差异，不能择有利结论。
