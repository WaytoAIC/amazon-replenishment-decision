# 首次使用与数据接入

只在首次使用、换环境、来源失效或数据缺口影响判断时触发；已有确认和连接不重复问、不重装。先探测当前可用MCP、CLI、API和项目文件，不能只因少了某个品牌工具就停止。探测不输出凭证，也不自动购买套餐、修改ERP或更改全局配置。

## 1. 先给接入体检，再集中补最少信息

按“来源 → 当前状态 → 已取得数据/截点 → 能做的判断 → 缺失影响 → 下一步方案”输出简短清单。状态区分可发现、读取成功、无匹配记录、未安装/未配置、鉴权/权限失败、无此能力；不是只列安装清单。

优先读取已有范围和规则；缺少时集中确认：项目根、授权店铺/站点与商品范围、匿名要求、经营目标和已确认SOP。真实映射留私有文件，用户只看稳定代号。新用户的目标、安全/覆盖、整箱/MOQ及指标来源须由其确认，不能继承示范项目的公司规则。能从资料查清的先查。

| 数据能力 | 优先方案 | 未接入时给出的可行替代 |
|---|---|---|
| 内部销量、流量、广告、利润、库存 | 已授权赛狐或现有ERP/API/CLI；先做一商品只读验收 | ERP或卖家后台导出的CSV/XLSX；缺访客时可做需求/库存计算但不能完整拆流量与转化 |
| 采购、生产、发运、接收 | 现有ERP计划/订单/货件关联；物流动态用已有货代或承运商入口 | 对应单据导出及人工履约承诺；只有库存表时只能给现货覆盖和缺口条件，不能承诺到货接续 |
| 市场、关键词与竞品 | 卖家精灵MCP | 供应商同站点同周期导出；或有权限的Amazon品牌分析/搜索数据。来源与层级不同要说明，不声称等价 |
| 业务规则、箱规、活动计划 | 已有SOP、商品主数据和活动文件 | 给出缺项表；没有正式参数仍可展示历史基线和条件方案，正式数量/最晚下单日保留未知 |

## 2. 卖家精灵 MCP 的具体补充方法

1. 先看当前客户端工具清单是否已有SellerSprite；已有则复用，不再安装。选择一个已授权对象执行最小只读查询，验收业务状态、映射及数据日期。
2. 没有连接：到[官方开放平台](https://open.sellersprite.com/mcp)确认MCP权限/额度，在“我的密钥”获取个人密钥；普通网页会员是否含MCP以账号页面为准，不代购。
3. 在客户端新增远程Streamable HTTP服务器：URL为 `https://mcp.sellersprite.com/mcp`，请求头名固定 `secret-key`，值由用户在客户端安全配置中填写。密钥名称不是请求头名；不要求把密钥贴聊天、不把带密钥的URL放文档或仓库。下面是通用客户端示意，不是所有客户端可直接导入的格式：

```json
{"mcpServers":{"sellersprite-mcp":{"type":"streamableHttp","url":"https://mcp.sellersprite.com/mcp","headers":{"secret-key":"<在客户端本地填写>"}}}}
```

4. 客户端差异按[官方接入说明](https://open.sellersprite.com/mcp/16)、[Codex说明](https://open.sellersprite.com/mcp/40)、[OpenClaw说明](https://open.sellersprite.com/mcp/43)操作，优先使用安全请求头/客户端密钥管理，避免密钥进入命令历史。字段和菜单以当前客户端为准，不把Bearer认证误当成secret-key。
5. 回读服务器列表；连接不明确先回读，不重复创建。刷新会话后确认工具出现，做一次业务读取，并报告实际覆盖。认证/额度失败给出对应修复步骤；缺历史数据用导出方案，不循环重试。

接入参数核对日期：2026-10-23，来自供应商官方说明。

## 3. 内部系统与文件最小数据方案

- 有内部API：由管理员开通对应账号、店铺、数据范围的只读权限；在受控密钥管理中配置凭证，必要时按该服务要求配置白名单。用一商品验证授权、日期、单位和分页。凭证、字段及签名按现有适配器/官方文档，不编造API地址。
- 赛狐适配器在当前项目已存在时可复用；其他使用者未安装它，不把本机脚本视为包内能力。没有适配器可先导表，不要求为了试用Skill编写完整API集成。
- 推荐私有文件分表：日销售（匿名对象、日期、销量，选填访客/广告/费用）；库存（对象、快照、真正可售、预留/不可售）；供给批次（匿名批次、对象、分配量、阶段、关联批次、发运/接收/可售日期及依据）；规则（有效期、定位/分级/生命周期、箱规/MOQ、交期与目标来源）。关键未知留空，不填0。
- 市场导出至少包含：匿名对象或匿名词、站点、父子体/节点层级、指标、单位/币种、观测日期、来源、估算标记。真实映射另存私有区，不上传公共仓库。
- 适配已有列名，不强迫用户重新录入。最低需要销量、可售库存及日期才能给现货覆盖；没有可售日期、正式需求或参数，不给可批准的完整采购数量与时间。

## 4. 保存接入状态并继续工作

在项目被忽略的私有目录记录连接名称（不含密钥）、授权范围、来源版本、最近成功读取、截点及已确认规则。可保存 `onboarding-status.json`，不写真实配置到Skill。下一轮先复用并检查过期，不重复询问已确认项目。

无市场工具时继续内部决策并标“外部归因未验证”；无采购进度时给现货风险与条件方案；无内部销量时外部估算仅支持市场研究，不能出真实补货单。接入完成不等于业务决策已验证，更不代表下单授权。
