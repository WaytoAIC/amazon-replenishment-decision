# 业务风险、归因与四角色协同

## 1. 两类核心异常

异常对象是“新的销售速度与库存、供给节奏不匹配”，不把接口缺字段等技术事项当业务异常主体。日销变化是核心驱动，供应延迟也可在日销不变时触发风险。

- **断货风险**：在某日下一批有效供应尚未可售，预计现货不足以满足需求；或者安全缓冲已不足。分别展示安全线与实际缺货线，不能混为一个期限。
- **滞销风险**：销售速度下降或来货未同步收缩，按正式需求目标/复评周期产生过量库存。没有目标阈值、季节截止或消化要求时，只报告预计覆盖、剩余量、占资及变化，不自造天数阈值。
- 同一商品允许先断后积压；不能因期末总库存足够，就隐藏到货前缺货。

比较：历史销售/原预测 → 新需求 → 无动作结果 → 现有供应按计划履约结果 → 可行补救结果 → 延误压力情景。压力时长必须标假设；原预计送达窗不能换名为可售承诺。

## 2. 状态与改善空间

| 状态 | 判断依据 | 推荐方向 |
|---|---|---|
| 正常 | 已有供应按需接续且缓冲满足规则；或需求/库存与目标匹配 | 保持计划，列下一触发条件 |
| 有风险，可改善 | 已核实的采购、调拨、分批、物流或运营方案能消除缺口/过量 | 明确方案、责任和最晚期限 |
| 能补上，但缓冲小 | 当前履约可以接上，小幅销量变化/延误即导致风险 | 标记关键货件；物流重点跟踪，供应链并行准备后手，运营同步更新需求 |
| 已无法完全避免 | 经确认最快可行方案仍有缺口，或不可撤回库存仍超出可消化量 | 标损失区间/数量、还能减少多少，提交必要取舍 |

最早可售时间未知或备选可行性未经证实，不能定性“可解决”或“已无解”；写“改善能力待核”及负责人、截止和所需结果。可部分改善时同时给改善量与剩余不可避免损失。无动作风险与动作后风险分开，动作未执行不能把风险改为已消除。

## 3. 计算要回答什么

- 现货支撑日数 = 当前可售 / 更新后的日销；日销为0时显示无销量与库存暴露，不除0，也不认定永久无需求。
- 每日期末库存 = max(0,期初库存 + 当日可售补充 - 当日需求)。当日未满足需求另记，后到货不能抹掉此前损失；不要把未售需求自动当未来积压订单。
- 安全库存 = 对应日销 × 已确认安全天数；分别输出首次低于安全日期与首次需求未满足日期。
- 供应未按日期分配时：总量对照只能作粗筛，正式判断应检查每段时间。接收残量、超收、共享归属与已有单据重复由助手核验，不用技术清单代替业务结论。
- 按日工具默认日初可售，临界接续须核实日内时点或加一天压力；输出6位小数用于展示，内部Decimal保留精度，不能将显示取整代替正式整箱计算。
- 原SOP：备货量 = (备货时长 + 安全天数) × 预测日销 - (当前库存 + 在途库存)。其中仅可在对应时段使用的供给才能抵扣。区间端点和核心修正分别列条件，不取中值、不混模型。
- 历史基线优先采用当前项目确认模型；7/14/30各窗口均销×0.5/0.3/0.2仅为可提议的候选；7日维持及其他模型只作显式敏感性，不任意替换主基线；原预测没有留存时不冒充“预测失准”。断货/链接问题先查，零销量不自动等于低需求。
- 对减速风险展示：原/新日销、需求下修量、现存/未发/在途/到仓各段数量、原计划继续执行的后果、可撤回或可调整部分、动作后剩余库存。不要用低ROI直接砍有利润的核定需求。

## 4. 归因与证据

分三层，不把症状当原因：
1. **触发**：日销或交期发生了什么变化，是否早于风险出现。
2. **失配环节**：销售计划是否传给供应链、采购/生产能否同步、物流/接收是否偏离；正常物流也可能跟不上已提高的销售速度。
3. **责任与根因**：有记录证据才确认，不能从相关性、一个超期残量或一张无归属计划判责任。

先按 [自主查数与归因流程](evidence-investigation.md) 查主动调整（活动、广告、价格、产品策略与目标），再比较流量、转化和市场线索；广告/自然访问须有拆分证据。外部季节、竞品、流量改变没有直接证据时只作假设。供给侧对比原承诺、最新进度、计划传递及调整记录。每个原因标“已核实/待验证/暂无法判断”，给支持证据和替代解释。助手先查已有入口；只有查不到且确需人的记录或承诺才列角色动作，并说明调查边界。缺信息不妨碍提出可逆的补救建议，但不能声称已执行。

## 5. 决策行为

- 供给足量按时：不新增采购，继续推进生产/发货/接收；正常不等于不跟踪。
- 有净缺口、常规来得及：复用已归属计划或新增采购，给整箱量与最晚下单/发货时间。
- 数量足但时间赶不上：先核现货、调拨、分批、加急；不能仅放大普通采购量。
- 计划内增长：优先协调供给；不可补救时运营提出销售节奏与影响，老板决定取舍，不自动缩量。
- 销量下滑/供给过量：依次检查未下单计划调整、未生产订单协商、分批/延后发货、在途处置、到仓消化。真实订单调整只提建议，不自动取消。
- 滞销消化：运营提出恢复流量、促销或其他销售方案及消化量、利润影响，供应链同步减缓后续来货；不能一边消化一边按旧计划补。
- 已无法避免：给预计缺货天数/未满足需求，或不可撤回库存及资金影响；比较能减少多少损失和代价，老板决定权限外事项。
- 缺证据：保留条件数量、时间界限与待查动作；正式量未知用空值，真正无缺口才用0。

桥接、常规采购与原计划不相加作总需求；落实一批后重算剩余量。对每个方案说明到货日期、成本来源、可行性与剩余风险，不把“可加急/可催单”当交付结论。

## 6. 四个角色

| 角色 | 负责 | 必须交付的具体信息 |
|---|---|---|
| 运营 | 日销归因、销售预测/计划与调整方案 | 原/新日销、计划持续期、增长是否主动、调整销量及影响 |
| 供应链 | 开发/供应商、采购、生产、备料至可发货 | 各批数量、承诺可发日期、能否催单/分批/替代供应、成本及后手 |
| 物流 | 发出后运输、清关、接收和上架跟踪 | 当前位置/下一节点、最晚出发/交接、预计真正可售、延误预警与改渠道方案 |
| 老板 | 经营目标、资金、权限外费用与不可避免损失 | 哪个选项需要决定、影响和最晚决策时间 |

供应链与物流共同核交接及全链路时间；关键货件即使运输正常，缓冲小也须物流重点跟进、供应链备选、运营更新需求。动作统一格式：角色 → 做什么 → 最迟何时 → 输出什么 → 谁据此接续 → 失约怎么升级。姓名未提供只分配角色，不编造人员或承诺。

接口字段、分页、映射和计算核验由助手处理，不能把“解释quantity字段/检查schema”等任务布置给业务部门。真实收货数量、仓内实物、位置和承诺需要人工核实，才由对应角色提供；无法补查时说明具体业务影响，不新增第五个角色。
